# HTTP API

Через API к команде агентов обращаются другие программы: сайт, CRM, скрипты,
сервисы автоматизации.

## Запуск

```bash
pip install -e ".[api]"
python -c "import secrets; print(secrets.token_urlsafe(32))"   # создать ключ
# в .env: PRIZOLOV_API_KEYS=<ключ>  (несколько - через запятую)
prizolov api                      # http://127.0.0.1:8800
prizolov api --host 0.0.0.0 --port 9000
prizolov api --scheduler          # плюс задачи по расписанию в этом процессе
```

Интерактивная документация (Swagger) — `/docs`, схема OpenAPI — `/openapi.json`.

## Доступ

Каждый запрос к `/v1/...` — с ключом в одном из заголовков:

```
Authorization: Bearer <ключ>
X-API-Key: <ключ>
```

Без ключа или с неверным ключом — `401`.

Как работает защита:

- Без ключей в настройках сервер не запускается; ключи короче 16 символов не
  принимаются.
- Ключи сравниваются за постоянное время, поэтому их нельзя подобрать по времени
  ответа.
- По умолчанию сервер слушает только `127.0.0.1`. Сам сервер работает по обычному
  HTTP. Чтобы открыть его в сеть, поставьте впереди HTTPS-прокси (nginx, Caddy),
  иначе ключ передаётся открытым текстом.

Каждый ответ содержит заголовки `X-Powered-By` и `X-Project-Id` (авторство Prizolov
Agent OS). Ошибки приходят в виде `{"detail": "текст"}`.

## Задачи агентам

Задача может идти минуты: агенты ищут данные, считают, проверяют ответ. Поэтому
работа идёт в фоне.

### `POST /v1/tasks` → 202

```json
{"message": "Спрогнозируй курс юаня ЦБ на неделю", "session_id": "client-42"}
```

- `session_id` необязателен. С ним задача продолжает диалог (агент помнит
  предыдущие сообщения), без него создаётся новый диалог. Допустимы латиница,
  цифры, `_` и `-`, до 64 символов.
- Если в диалоге ещё выполняется предыдущая задача, ответ — `409`.
- Ответ — описание задачи (см. ниже) со статусом `queued`.

### `GET /v1/tasks/{id}`

```json
{
  "id": "c2dffe24f6554346",
  "kind": "chat",
  "session_id": "client-42",
  "request": "Спрогнозируй курс юаня ЦБ на неделю",
  "status": "done",
  "text": "Ответ агента в Markdown…",
  "stop_reason": "end_turn",
  "error": "",
  "usage": {"input_tokens": 18234, "output_tokens": 1520, "cost_usd": 0.0779, "iterations": 3},
  "progress": ["→ Директор → Рыночный аналитик: …", "✓ Рыночный аналитик закончил"],
  "files": ["charts/CNY-20261009-101500.png"],
  "created": 1791562376.29,
  "finished": 1791562410.81
}
```

Возможные значения `status`:

| Статус | Что значит |
|---|---|
| `queued` | задача в очереди |
| `running` | задача выполняется |
| `waiting_approval` | агент ждёт подтверждения действия |
| `done` | готово; ответ в `text` |
| `error` | ошибка; причина в `error` (например, нет ключа Anthropic или превышен лимит расходов) |

Опрашивайте задачу раз в 1–3 секунды. Файлы из `files` скачиваются через
`/v1/files/...`.

### `GET /v1/tasks?limit=20`

Последние задачи этого процесса сервера. Последние 200 хранятся в памяти и пропадают
при перезапуске; сами диалоги хранятся в базе.

### Подтверждения

Запись файла требует согласия человека:

- `GET /v1/approvals` — ожидающие запросы:
  `[{"id": "…", "job_id": "…", "tool": "write_file", "description": "Записать файл …"}]`.
- `POST /v1/approvals/{id}` с телом `{"allow": true}` или `{"allow": false}`.

Без ответа за 5 минут действие отклоняется.

## Диалоги

| Метод | Что делает |
|---|---|
| `GET /v1/sessions?limit=20` | сохранённые диалоги: `id`, `title`, `messages`, `updated_at` |
| `DELETE /v1/sessions/{id}` | удалить диалог (204) |
| `POST /v1/sessions/{id}/feedback` | оценка последнего ответа: `{"positive": false, "comment": "Указывай источник"}`. Замечание становится уроком агенту; в ответе — `{"lesson": "…"}` |

## Отчёты и файлы

### `POST /v1/reports`

Прогноз по активу без Claude: бесплатно и без ключа Anthropic.

```json
{"symbol": "GOLD", "source": "cbr", "horizons": [1, 7, 15, 30], "history_days": 365}
```

- `source` необязателен: `yahoo`, `moex` или `cbr`. Без него источник определяется
  по тикеру: коды ЦБ (`GOLD`, `SILVER`, `USD`, `EUR`, `CNY`…) — ЦБ, остальное — Yahoo.
- `horizons` — от 1 до 365 дней.
- `history_days` — от 30 до 3650.

В ответе:

- текущее состояние в `summary`: последняя цена, изменение, RSI, волатильность,
  просадка;
- `forecasts` — прогноз на каждый горизонт: `median`, `low_80`/`high_80`,
  `low_95`/`high_95`, `probability_up`, `method_name` и `reliability`;
- `reliability` — на скольких прогнозах проверен метод и процент попаданий;
- готовый отчёт в `markdown`, пути к `report_file` и `chart_file`.

Если источник недоступен — `502`.

### Файлы и документы

| Метод | Что делает |
|---|---|
| `GET /v1/files/{путь}` | скачать отчёт или график; доступны только папки `reports/` и `charts/` рабочей папки |
| `PUT /v1/inbox/{имя файла}` | загрузить документ: тело запроса — сам файл. Поддерживаются PDF, DOCX, XLSX, CSV, TXT, MD, до 20 МБ. Файл сохраняется в `inbox/` и сразу индексируется |
| `GET /v1/knowledge/search?q=срок+оплаты&limit=6` | поиск по базе знаний: `path`, `location`, `text`, `score`, `source` |

```bash
curl -X PUT localhost:8800/v1/inbox/dogovor.pdf -H "X-API-Key: $KEY" --data-binary @dogovor.pdf
```

## Прогнозы, качество, расходы

| Метод | Что возвращает |
|---|---|
| `GET /v1/forecasts` | `counts` — прогнозов по статусам; `methods` — соревнование методов по классам активов и горизонтам: проверка на истории (`backtest`) и реальные сверки (`live`), процент попаданий в интервалы 80%/95%, точность направления, средняя ошибка |
| `POST /v1/forecasts/verify` | сверить наступившие прогнозы с фактическими ценами (требует доступа к источникам) |
| `GET /v1/quality?days=30` | отказы инструментов, оценки критика, ваши оценки, попытки prompt injection |
| `GET /v1/budget` | лимиты, расходы сегодня и всего, по дням |
| `GET /v1/status` | состояние системы: агенты, память, база знаний, открытые диалоги и задачи API |
| `GET /health` | проверка работы (без ключа): версия, автор, ID проекта |

## Расписание

| Метод | Что делает |
|---|---|
| `GET /v1/schedules` | список задач |
| `POST /v1/schedules` → 201 | создать задачу (тело — ниже) |
| `POST /v1/schedules/{id}/pause` и `/resume` | приостановить или включить |
| `POST /v1/schedules/{id}/run` → 202 | выполнить сейчас; результат — `GET /v1/tasks/{id}` |
| `DELETE /v1/schedules/{id}` → 204 | удалить; встроенную сверку удалить нельзя (409), только приостановить |

Тело `POST /v1/schedules`:

```json
{"schedule": "по будням 9:00", "kind": "report", "symbol": "GOLD", "horizons": [1, 7, 15, 30]}
{"schedule": "по понедельникам 10:00", "kind": "task", "task": "Обзор рынка металлов за неделю"}
```

Расписание задаётся словами («ежедневно 09:00», «по будням 9:30», «каждые 6 часов»)
или строкой cron, в часовом поясе `PRIZOLOV_TIMEZONE`. Результаты сохраняются в
`reports/`.

Задачи по расписанию выполняет только процесс с планировщиком: `prizolov api --scheduler`,
`prizolov telegram` или `prizolov scheduler`. Запускайте только один из них.
