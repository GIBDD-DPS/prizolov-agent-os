# Как устроена Prizolov Agent OS

## Общая схема

```
 Терминал · Веб-интерфейс · Telegram-бот · HTTP API · MCP · Расписание
                                   │
                             Ядро (Kernel)
                                   │
                       Директор (оркестратор)
      ┌─────────┬──────────┬───────┼────────┬─────────┬────────┐
  ассистент исследователь писатель финансовый рыночный юрист  госзакупки
                                   аналитик   аналитик
                                   │
      Инструменты · Память (SQLite) · База знаний · Прогнозы · Бюджет · Трассировка
```

| Модуль | Что в нём |
|---|---|
| `prizolov_os/agent.py` | агент: роль, инструменты, цикл «модель → инструменты → модель» |
| `prizolov_os/core/` | ядро (`Kernel`) и Директор (`Orchestrator`) |
| `prizolov_os/agents/` | семь специалистов и их промпты |
| `prizolov_os/llm/` | клиент Claude: запасная модель на стороне сервера, адаптивные рассуждения, кэш промптов, сжатие истории |
| `prizolov_os/tools/` | инструменты: файлы, калькулятор, дата, рынки, графики, память, база знаний |
| `prizolov_os/market/` | котировки Yahoo Finance, Мосбиржи, ЦБ РФ |
| `prizolov_os/analytics/` | анализ ценовых рядов и движения денег |
| `prizolov_os/forecasting/` | методы прогноза, проверка на истории, калибровка, журнал |
| `prizolov_os/improvement/` | критик, уроки, версии промптов, инструменты от агентов |
| `prizolov_os/security/` | защита от prompt injection |
| `prizolov_os/knowledge.py` | база знаний по документам |
| `prizolov_os/scheduler.py` | расписание задач |
| `prizolov_os/analytics/statements.py`, `categories.py` | выписки 1С/CSV/Excel, статьи расходов |
| `prizolov_os/payment_calendar.py` | плановые платежи и прогноз остатка по дням |
| `prizolov_os/portfolio.py` | портфель инвестора, T-Invest API, риск и стресс-тесты |
| `prizolov_os/tenders.py` | поиск госзакупок в ЕИС |
| `prizolov_os/accuracy.py` | открытая статистика точности прогнозов |
| `prizolov_os/reports.py` | отчёты по активам без модели |
| `cli/` | терминал, Telegram-бот (`cli/telegram`), HTTP API и веб-интерфейс (`cli/api`), MCP-сервер (`cli/mcp_server.py`) |

## Агенты

**Директор** получает задачу пользователя. Простые вопросы он решает сам; иначе
поручает части задачи специалистам через инструмент `delegate` и собирает итог.

- **Порядок поручений.** Независимые поручения Директор даёт одним ответом, и они
  выполняются одновременно (`PRIZOLOV_PARALLEL`). Зависимые — по очереди: например,
  сначала исследователь, потом писатель.
- **Инструменты Директора:**
  - `remember` и `recall` — факты о пользователе;
  - `search_knowledge` — поиск по документам;
  - `schedule_task` — регулярные задачи, с подтверждением;
  - `propose_tool` — предложить новый инструмент.

| Специалист | Инструменты |
|---|---|
| ассистент | калькулятор, дата, файлы рабочей папки |
| исследователь | поиск и чтение веб-страниц (серверные инструменты Claude), чтение файлов, база знаний |
| писатель | файлы (запись с подтверждением), база знаний |
| финансовый аналитик | анализ выписки (1С, CSV, Excel) со статьями, платёжный календарь и плановые платежи (запись — с подтверждением), графики, калькулятор |
| рыночный аналитик | анализ рынка и прогноз, анализ цен из файла, графики, анализ портфеля |
| юрист по договорам | чтение документов, сравнение версий, база знаний, запись заключения (с подтверждением) |
| специалист по госзакупкам | поиск закупок в ЕИС, чтение и сравнение документации, база знаний, калькулятор |

Каждый агент получает перед задачей уроки из прошлого опыта, подходящие к запросу.

## Самообучение

1. **Самопроверка.** После ответа с участием специалистов критик (отдельный запрос к
   модели со структурированным ответом) ставит оценку от 1 до 10 и перечисляет
   замечания. Если оценка ниже 7, Директор дорабатывает ответ по замечаниям.
   Режим задаёт `PRIZOLOV_SELF_CHECK`.
2. **Уроки.** Из ваших оценок (`/bad комментарий`) и замечаний критика модель
   формулирует короткий урок конкретному агенту. Уроки хранятся в базе и
   подмешиваются к похожим задачам. Посмотреть и удалить уроки:
   `/lessons`, `/unlearn N`.
3. **Промпты.** Когда у агента накопились уроки, `/improve` предлагает новую версию
   его промпта. Она применяется только после `/approve-prompt N`; откатить её можно
   командой `/rollback агент`.
4. **Инструменты от агентов.** Агент может предложить свой инструмент на Python.
   Код проверяется статически: модули только из белого списка, без опасных функций
   и скрытых атрибутов. Подключается инструмент только после того, как вы прочитали
   код и одобрили его (`/approve-tool`). Работает он в отдельном процессе с
   таймаутом 10 секунд, пустым окружением и лимитами памяти.
5. **Монитор качества.** Монитор считает отказы инструментов и источников данных.
   Если за неделю у инструмента не меньше 10 вызовов и больше 30% из них с ошибкой,
   агент получает урок.

## Прогнозы, которые учатся на ошибках

Модель прогнозирует логарифм цены. Неопределённость берётся из волатильности за
последние 250 наблюдений.

**Методы-соперники:**

| Метод | Идея |
|---|---|
| долгосрочный тренд | средний дрейф за всю историю |
| без тренда | цена в среднем не меняется (случайное блуждание) |
| недавний импульс | дрейф за последние 60 наблюдений |
| возврат к средней | цена тянется к 50-дневной средней |

**Как выбирается и проверяется прогноз:**

1. **Проверка на истории (walk-forward).** Каждый метод прогнозирует из прошлых
   точек ряда, до 60 точек, и сравнивается с тем, что было на самом деле.
   Считаются:
   - процент попаданий в интервалы 80% и 95%;
   - точность направления;
   - средняя ошибка.
2. **Выбор метода.** Выбирается метод с наименьшей ошибкой. Когда накопятся реальные
   сверки, они учитываются с двойным весом.
3. **Калибровка.** Интервалы расширяются или сужаются так, чтобы в 80%-й интервал
   попадало около 80% фактов; медиана сдвигается на систематическую ошибку.
   Калибровка включается от 10 сверок и ограничена: множитель интервала от 0,5 до 2,
   сдвиг — не больше половины неопределённости. Отдельно по классам активов
   (металлы, акции, валюты, криптовалюты…) и горизонтам. Сброс:
   `/calibration-reset`.
4. **Надёжность в ответе.** К каждому прогнозу приложено:
   - на скольких прогнозах проверен метод;
   - какой процент попал в интервал;
   - как часто угадано направление;
   - результаты реальных сверок.

   Если направление угадывается не чаще 55% случаев, агент предупреждает, что
   прогноз направления ненадёжен.
5. **Журнал и сверка.** Прогноз записывается в журнал. Когда его срок наступает,
   `/verify` (или ежедневная задача в 08:50) берёт фактическую цену и обновляет
   статистику. Если факт не удаётся получить 30 дней, прогноз помечается
   несверяемым. По классам активов, где прогнозы часто не сбываются, рыночный
   аналитик получает урок.

Соревнование методов и точность — `/forecasts` или `GET /v1/forecasts`.

Выписки движения денег анализируются похоже. Агент считает средний дневной поток и
выдаёт прогноз остатка с интервалами и вероятностью уйти в минус. Эти прогнозы
сверяются по новым выпискам.

## База знаний

Документы рабочей папки (PDF, DOCX, XLSX, CSV, TXT, MD) индексируются локально в той
же базе SQLite:

- **Нарезка.** Текст делится на фрагменты по 1000 символов с перекрытием 150.
- **Поиск.** Работает через полнотекстовый индекс FTS5 с ранжированием BM25.
- **Окончания слов.** Слова сравниваются по первым 5 буквам, поэтому «договора»
  находит «договору».
- **Обновление.** Изменённые файлы переиндексируются автоматически перед поиском;
  полная переиндексация — `/index full`.
- **Приватность.** Данные никуда не отправляются, кроме фрагментов, которые агент
  включает в запрос к модели.

## Безопасность

- **Рабочая папка.** Агенты работают с файлами только в ней: пути вне её
  отклоняются. Запись — только с подтверждения человека (в терминале, кнопками в
  Telegram, через `/v1/approvals` в API).
- **Prompt injection.** Веб-страницы, документы и файлы пользователя — это данные,
  а не команды. Их содержимое оборачивается в `<untrusted_data>`, и все агенты
  получают правило не выполнять инструкции из данных. Подозрительные фразы
  («игнорируй предыдущие инструкции», «you are now…») отмечаются, предупреждение
  видно пользователю и учитывается в `/quality`.
- **Доступ.** Telegram-бот отвечает только по белому списку ID. HTTP API требует
  ключ.
- **Расходы.** Лимиты на задачу и на день; при превышении работа останавливается с
  понятным сообщением.
- **Трассировка.** Каждый шаг (запросы к модели, вызовы инструментов, поручения)
  пишется в `logs/trace-*.jsonl`. Полные тексты пишутся только с
  `PRIZOLOV_TRACE_CONTENT=true`.

## Авторство

- **Единый источник.** Версия и данные автора задаются в `prizolov_os/__about__.py`.
- **Шапки файлов.** Каждый файл проекта начинается с шапки
  `Prizolov Agent OS 0.3.0 | Author: Dm.Andreyanov | Brand: Prizolov Lab | © 2026` и
  тегов SPDX. Шапку проверяет CI (`scripts/stamp_headers.py --check`).
- **Метки авторства в работе программы:**
  - база данных хранит метку проекта;
  - запросы к источникам данных идут с User-Agent Prizolov Agent OS;
  - ответы HTTP API содержат заголовки авторства;
  - отчёты и файлы агентов подписываются.
- **Лицензия.** Apache 2.0: при распространении обязательно сохранять [NOTICE](../NOTICE).
